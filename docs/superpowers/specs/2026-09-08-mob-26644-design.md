# MOB-26644 — ReactNativeDemo test build otomasyonu ve tasarım hizalaması

**Tarih:** 2026-09-08
**Jira:** [MOB-26644](https://winsider.atlassian.net/browse/MOB-26644) — `[ReactNative] Automate updating the test build (ReactNativeDemo)`
**Epic:** MOB-26623 `[SDK] CI/CD & DevOps Improvements AI`
**Kardeş task'lar:** MOB-24948 (SwiftDemo/KotlinDemo, kapandı — prior art), MOB-26643 (FlutterDemo, To Do — aynı kararlar geçerli)
**Etkilenen repo'lar:** `useinsider/react-native-insider`, `useinsider/ReactNativeDemo`

---

## 1. Problem

ReactNativeDemo, `react-native-insider` release sürecinin dışında. Release workflow'ları
(`create-release.yml`, `update-version-number.yml`, `publish-release.yml`) demo repo'ya hiç
dokunmuyor; demo'yu güncelleyen tek şey elle çalıştırılan `npm run sync`. Sonuç: demo `main`
`react-native-insider@8.0.0` pinliyor, yayınlanan sürüm 8.1.0. Bir release demo'nun build'ini
bozarsa ne önceden uyarı alınıyor ne de sonradan düzeltiliyor.

Buna ek olarak demo'nun iOS extension'ları hâlâ Objective-C ve görsel dili native demo'lardan
(KotlinDemo / SwiftDemo) ayrışmış durumda.

## 2. Kapsam

**Kapsam içi**

1. `react-native-insider`'da release PR'ları için ReactNativeDemo build gate'i (Android + iOS).
2. `publish-release` sonrası ReactNativeDemo `main`'de sürüm bump otomasyonu.
3. ReactNativeDemo'nun iki iOS notification extension'ının Objective-C'den Swift'e taşınması.
4. ReactNativeDemo'nun `mobileandroid` demo'sunun görsel sistemine geçirilmesi (tek light tema).

**Kapsam dışı**

* `react-native-insider` public API'si ve native bridge.
* `nh` varyantı — demo onu kullanmıyor, `publish-release-nh` demo'ya dokunmaz.
* App Frames ekranı — RN SDK'da App Frames API'si yok (bkz. Karar 1). `mobileandroid`'in
  unmerged `feature/MOB-29434` branch'ine hiçbir bağımlılık yok.
* `npm run sync` — local geliştirme için kalmaya devam eder.
* Demo'nun ekran akışı, etiketleri ve buton metinleri; sadece görünüm değişir.

## 3. Alınan kararlar

| # | Karar | Gerekçe |
|---|---|---|
| 1 | App Frames kapsam dışı | RN SDK'da App Frames API'si yok. Gerekirse ayrı task açılır. |
| 2 | ObjC→Swift bu tickette | MOB-26643 Flutter tarafında aynı işi kendi kapsamına aldı; simetri korunuyor. |
| 3 | Bump `main`'e direkt commit | SwiftDemo'daki "bump up sdk versions" commit'lerinin otomatikleşmiş hali. PR fallback'i yok. |
| 4 | Jira subtask açılmıyor | Tek ticket; repo başına ayrı PR (iki repo → iki PR). |
| 5 | Tek light tema | Native demo'lar tek light tema (navy + orange) kullanıyor; `useColorScheme` dallanması kaldırılıyor. |

## 4. Prior art

`mobileandroid/.github/workflows/build-demo-application.yml` (MOB-26788) ve
`mobile-ios/.github/workflows/build-demo-application.yml` (MOB-26737) tam da bu işi yapıyor ve
cross-repo: ayrı repo'daki demo'yu (`useinsider/KotlinDemo`, `useinsider/SwiftDemo`) `main`'den
checkout edip PR'daki SDK'ya local olarak linkleyip build ediyor. Yeni workflow bu şablonu izler.

Post-publish bump'ın precedent'i **yok**: `mobileandroid` ve `mobile-ios`'un `publish-release.yml`
dosyaları hiçbir demo repo'ya yazmıyor. Native demo'lar sürümü hiç pinlemiyor
(`KotlinDemo/gradle/libs.versions.toml` → `insider_sdk = "+"`, `SwiftDemo/Podfile` →
`pod 'InsiderMobile'` sürümsüz), bu yüzden bump'a ihtiyaç duymamışlar. RN'de aynısı mümkün değil:
`package-lock.json` repo'da commit'li ve `npm ci` onu okuduğu için `"latest"` demek demo'yu güncel
yapmaz, sadece pin'i görünmez kılar. Bu yüzden RN'de pin + otomatik commit tek çalışan yol.

## 5. İş 1 — Release-PR build gate

**Dosya:** `react-native-insider/.github/workflows/build-demo-application.yml` (yeni)

**Trigger** — `mobileandroid` ile birebir:

```yaml
on:
  pull_request:
    branches: [master]
    types: [synchronize]
concurrency:
  group: react-native-build-demo-${{ github.ref }}-${{ github.workflow }}
  cancel-in-progress: true
```

Her job `if: startsWith(github.event.pull_request.head.ref, 'release/')` taşır.

**İki job, iki runner.** `self-runner-node-high` Linux'tur — `publish-release.yml`'daki "Install
Ruby" ve "Install GitHub CLI" adımları yalnızca apt-get/dnf/yum/zypper/apk dallanıyor, brew yolu
yok. iOS build'i orada koşamaz.

| Job | Runner | Build komutu |
|---|---|---|
| `build-android` | `self-runner-node-high` | `./gradlew assembleDebug` (`ReactNativeDemo/android`) |
| `build-ios` | `instrosx001` | `xcodebuild -workspace ReactNativeDemo.xcworkspace -scheme ReactNativeDemo -sdk iphonesimulator -configuration Debug CODE_SIGNING_ALLOWED=NO build` |

**Ortak adımlar** (KotlinDemo job'ının yapısı):

1. `actions/create-github-app-token@v2`, `owner: ${{ github.repository_owner }}`.
2. `actions/checkout@v6` → `path: SDKs` (PR'daki `react-native-insider` kodu).
3. `actions/checkout@v6` → `repository: useinsider/ReactNativeDemo`, `ref: main`,
   `path: ReactNativeDemo`, App token ile. `continue-on-error` **yok**; checkout düşerse job kırmızı olur.
4. `actions/setup-node@v5` (Node 24, repo'daki diğer job'larla aynı).
5. SDK'yı demo'ya linkle — demo'nun kendi `sync` script'inin yaptığı iş:
   `npm install "$(npm pack "${GITHUB_WORKSPACE}/SDKs")"` (`ReactNativeDemo` dizininde çalışır).
   Flutter'ın `dependency_overrides` yaklaşımı port edilmez.
6. Log'a release sürümü (`github.event.pull_request.head.ref`'ten türetilir) ve
   `git -C ReactNativeDemo rev-parse HEAD` basılır.
7. Android job: JDK 17 (`actions/setup-java@v4`), `android-actions/setup-android@v3`,
   `gradle/actions/setup-gradle@v3`. iOS job: Ruby + CocoaPods (`maxim-lobanov/setup-cocoapods@v1.4.0`),
   `pod install`.

**Merge'ü ne bloklar.** Ticket'ın "`verify_pull_request_checks` bu job'ı saymalı" ifadesi teknik
olarak yanlış ve düzeltilmelidir: `devops/create_release_pull_request.sh` içinde bu fonksiyon
release branch'i **yaratılmadan önce** (satır 333) çalışıyor ve `GIT_TARGET_BRANCH=develop`'a giden
**feature PR**'larını doğruluyor; release PR ise `--base master` ile o adımdan sonra açılıyor
(satır 427), yani fonksiyon çalışırken release PR henüz mevcut değil. Bloklama tek mekanizmadan
gelir: **`master` branch protection'ında bu iki job'ın required status check olarak
işaretlenmesi** — bu bir repo ayarı, kod değil. `master` protected olduğu doğrulandı; required
check listesini okumak admin yetkisi ister.

**Kabul kriterleri**

* Job'lar yalnız head branch'i `release/*` olan, `master`'a giden PR'ların `synchronize`
  event'inde koşar; başka PR'larda koşmaz.
* Demo, PR'daki SDK koduyla linklenir; npm registry'den sürüm çekilmez.
* Android veya iOS build'i patlarsa ilgili job non-zero exit verir.
* Demo checkout'u başarısız olursa job ayırt edilebilir bir hata mesajıyla düşer, sessiz geçmez.
* Job log'u test edilen release sürümünü ve ReactNativeDemo commit SHA'sını yazar.
* İki job `master` branch protection'ında required check olarak kayıtlıdır (DevOps adımı).

## 6. İş 2 — Publish sonrası sürüm bump'ı

**Dosya:** `react-native-insider/.github/workflows/publish-release.yml` (yeni job)

```yaml
update-demo-application:
  name: Update Demo Application (ReactNativeDemo)
  needs: [create-deployment, publish-release]
  if: ${{ needs.publish-release.outputs.state == 'success' }}
  runs-on: self-runner-node-high
  continue-on-error: true
```

`publish-release-nh` bu job'a `needs` vermez → nh varyantı demo'ya dokunmaz.

**Adımlar**

1. App token; iki checkout: `path: SDKs` (`devops/slack_notifier.sh` için) ve
   `useinsider/ReactNativeDemo@main` → `path: ReactNativeDemo`.
2. Git kimliği `insider-automation <devops@useinsider.com>`, `crazy-max/ghaction-import-gpg@v6`
   ile `commit.gpgsign true` — mevcut release commit'leriyle aynı.
3. `npm install react-native-insider@${VERSION} --save-exact` (`ReactNativeDemo` dizininde).
   npm registry propagation gecikmesi için 3 denemeli retry, denemeler arası 15 sn; ilk denemede
   404 beklenen durumdur.
4. `git diff --quiet -- package.json package-lock.json` → değişiklik yoksa `exit 0`, commit atılmaz.
5. Commit `chore(deps): bump react-native-insider to ${VERSION}`, `main`'e direkt push.
6. Herhangi bir adım düşerse `devops/slack_notifier.sh` ile bildirim gider; job
   `continue-on-error: true` olduğu için `publish-release` fail edilmez — paket o noktada zaten
   npm'de yayınlanmıştır.

**Kabul kriterleri**

* `publish-release` başarılı olduktan sonra ReactNativeDemo `main`'de `package.json` ve
  `package-lock.json` yayınlanan sürüme çekilir.
* `publish-release-nh` tarafından işlenen bir tag ReactNativeDemo'da hiçbir commit üretmez.
* Demo zaten yayınlanan sürümü pinliyorsa otomasyon 0 ile çıkar ve commit atmaz.
* Commit `insider-automation <devops@useinsider.com>` yazarlı ve GPG imzalıdır.
* Başarısız bump Slack'e düşer ve `publish-release` job'ını fail etmez.

**Açık risk (bu işi tek başına bloklayabilir).** `InsiderActionsApplication` installation'ının
`ReactNativeDemo`'ya **write** izni olduğu kanıtlı değil. KotlinDemo checkout'unun çalışması
yalnız *read* kanıtlıyor ve kopyalanacak bir write precedent'i yok. İlk implementasyon adımı bu
izni doğrulamaktır; yoksa DevOps'tan installation'a `ReactNativeDemo` + `contents: write`
eklenmesi istenir. ReactNativeDemo `main` korumalıysa direkt push reddedilir; bu durumda korumanın
gevşetilmesi mi yoksa PR fallback'ine geçilmesi mi gerektiği **task sahibine sorulur**, tek taraflı
PR yoluna sapılmaz.

## 7. İş 3 — iOS extension'ları Swift'e taşıma

**Hedef biçim** (`mobile-ios/ExampleSwift` ile aynı):

```swift
import InsiderMobileAdvancedNotification

public final class NotificationService: InsiderNotificationServiceExtension {
    public override var appGroupIdentifier: String { "group.com.useinsider.reactnativedemo" }
}
```

`NotificationViewController` da `InsiderNotificationViewController`'ı aynı şekilde subclass eder.

**Doğrulanması gereken bağımlılık.** Base class'lar `mobile-ios` kaynağında 2.3.1'de var ve
umbrella header'da Public olarak export ediliyor; ancak demo'ya yüklü yayınlanmış CocoaPods 2.3.1
xcframework'ünün `Headers/` klasöründe yalnız `InsiderPushNotification.h` ve `iCarousel.h` var.
İlk adım temiz bir `pod install` ile bunu doğrulamaktır. Base class'lar yayınlanan pod'da yoksa
**fallback**: mevcut `.m` davranışı birebir Swift'e çevrilir (`showInsiderRichPush`,
`interactivePushLoad`, `iCarousel` delegate/dataSource'ları). Dosya sayısı ve kabul kriterleri
değişmez, yalnız Swift dosyaları uzar.

**Birlikte düzeltilecek üç bug** (`origin/main` üzerinde, üçü birlikte rich push'u bozuyor):

| Yer | Şu an | Olması gereken |
|---|---|---|
| `ios/InsiderNotificationService/NotificationService.m:12` | `group.com.useinsider.mobile-ios` | `group.com.useinsider.reactnativedemo` |
| `App.tsx:135` | `group.com.useinsider.mobile-ios` | `group.com.useinsider.reactnativedemo` |
| `ios/InsiderNotificationContent/InsiderNotificationContent.entitlements:7` | `group.group.com.useinsider.reactnativedemo` | `group.com.useinsider.reactnativedemo` |

Doğru değer `ios/ReactNativeDemo/ReactNativeDemo.entitlements`'ta zaten
`group.com.useinsider.reactnativedemo`.

**Kabul kriterleri**

* `NotificationService.h/.m` ve `NotificationViewController.h/.m` silinir; yerlerine
  `NotificationService.swift` ve `NotificationViewController.swift` gelir.
* `ios/ReactNativeDemo.xcodeproj/project.pbxproj`'da `InsiderNotificationService` ve
  `InsiderNotificationContent` target'ları altında sıfır `.m` kaynak dosyası kalır.
* Üç app group değeri de `group.com.useinsider.reactnativedemo` olur.
* Fiziksel iOS cihazda panelden gönderilen zengin push: collapsed bildirimde görsel, expanded
  görünümde carousel çalışır.
* `README.md` satır 50 iki `.swift` dosyasını adlandırır.

## 8. İş 4 — Tasarım sistemi

Referans: `mobileandroid` `origin/develop` — `app/src/main/res/values/colors.xml`,
`app/src/main/res/font/kufam_*.ttf`. Unmerged `feature/MOB-29434`'e bağımlılık yok.

**Token katmanı.** `src/theme/` altında tek kaynak:

* `colors.ts` — `insider_navy #1B1F3B`, `insider_navy_dark #0E1027`, `insider_orange #FF5C35`,
  `insider_orange_dark #E5491F`, `insider_surface #F7F8FC`, `insider_surface_variant #EDEFF7`,
  `insider_on_surface #1B1F3B`, `insider_on_surface_variant #5B6075`, `insider_outline #D6DAE8`,
  `white`, `black`.
* `typography.ts` — Kufam ölçeği, `kufam_medium` ve `kufam_semibold` ağırlıkları.
* `spacing.ts` — ortak boşluk ölçeği.

Bu dosyaların dışında hiçbir `.tsx` hard-coded hex taşımaz. Bugün dağınık halde 8 ayrı değer var
(`#FFFFFF`, `#000000`, `#F3F3F3`, `#E57F74`, `#333333`, `#007BFF`, `#F0F0F0`, `#a8a8a8`).

**Font.** Kufam `.ttf` dosyaları `mobileandroid/app/src/main/res/font/`'tan
`ReactNativeDemo/assets/fonts/`'a kopyalanır; `react-native.config.js` + `npx react-native-asset`
ile iki platforma bağlanır (iOS `Info.plist` `UIAppFonts`, Android `assets/fonts`).

**Kart dili.** Yeni `src/components/Card.tsx`: beyaz zemin, 18 corner radius, 1px
`insider_outline` border, gölge yok (`elevation: 0`, `shadowOpacity: 0`).

**Tema modu.** Tek light tema. `useColorScheme()` dallanmaları `App.tsx`, `CustomSection.tsx`,
`Header.tsx`, `CustomButton.tsx` ve `src/insider/*.tsx` içinden kaldırılır.

**Kabul kriterleri**

* Dokuz `insider_*` değeri `src/theme/colors.ts`'te tanımlıdır ve dışında hex literal yoktur.
* Metin stilleri Kufam ailesini `kufam_medium` / `kufam_semibold` ağırlıklarıyla kullanır; font
  dosyaları iki platformda da yüklüdür.
* Her kart yüzeyi beyaz, 18 radius, 1px `insider_outline` border, gölgesizdir.
* Aynı ekran Android ve iOS build'lerinde aynı görünür.
* `useColorScheme` çağrısı repo'da kalmaz.
* Ekran akışı, ekran sırası ve tüm etiket/buton metinleri değişmemiştir.

## 10. Riskler ve açık işler

1. **App installation write izni** (İş 2'yi bloklayabilir) — doğrulanacak, yoksa DevOps talebi.
2. **`instrosx001` runner erişimi** — bu macOS runner'ın `react-native-insider` repo'suna açık
   olduğu doğrulanmadı; repo-scoped ise DevOps'tan istenmeli.
3. **Yayınlanmış `InsiderMobileAdvancedNotification` pod'unun base class'ları export etmemesi**
   (İş 3) — fallback tanımlı, kapsamı değiştirmiyor.
4. **`master` required status check kaydı** — kod değil repo ayarı; yapılmazsa gate yeşil görünür
   ama merge'ü bloklamaz.
5. **Ticket AC düzeltmesi** — `verify_pull_request_checks` maddesi Jira'da düzeltilmeli.
